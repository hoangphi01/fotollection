# Docs Guide — Fotollection

> **Last reviewed:** 2026-11-04
>
> The checklist for keeping docs, the website and the code in step ([ADR-0006](adr/0006-docs-as-code.md)). Before you commit, find every row below that matches your change and do all of it, in the same commit. Where a fact lives is mapped in [README.md](README.md); this page says **what to update when something changes**.

## 1. How to use it

1. Before any work, read this page and [LESSONS.md](LESSONS.md) in full (the `pre-work` skill, `.claude/skills/pre-work/`; owner, 2026-11-05).
2. Read the rows of §2 that match the change. Most changes match several rows: a new feature is "behaviour", "UI text" and often "website".
3. Update every file in the row. "Also check" lists files that change only sometimes; look at them and decide.
4. Run §3 before committing. CI runs the same checks.

## 3. Before every commit

**Docs move with code, in the same commit.** `scripts/check-docs.sh` fails when the working tree (or the last commit) changes `crates/`, `src-tauri/src/` or `ui/src/` without a doc, the CHANGELOG or a README, and the `docs-with-code` workflow checks every pushed commit the same way. A commit that truly needs no doc says `[no-docs]` and why in its message. **Every change works in Collage mode too** (owner, 2026-11-05): check it with two photos to a sheet, each with its own edits, with a photo picked and with none, in the panel and the sheet's preview, and with postcards on (LESSONS). **Before a push**, run `scripts/check-docs-with-code.sh origin/main..HEAD`: it checks every commit about to go out, as CI will (LESSONS 2026-11-05). It also checks that ROADMAP and STATUS give every FR the same phase.

**Check resources before, during and after every build and test run.** The dev machine has a small disk and little free swap; a full disk fails builds halfway, and heavy swap makes every timing meaningless.

- **Before:** `scripts/resources.sh` (free disk, memory pressure, swap, size of `target/`). It fails under 10 GB free; `scripts/resources.sh --clean` runs `cargo clean` when `target/` is over 12 GB.
- **During** a long build or a benchmark: watch it (`top -l 1 -o mem -n 8`, `df -h .`) and stop it before the disk fills. With little free memory, build with `CARGO_BUILD_JOBS=4` and never beside the dev app (LESSONS 2026-11-05).
- **After:** run `scripts/resources.sh` again and note what the build or test cost. Benchmarks are only logged when memory pressure was normal and swap was not growing ([OPTIMIZATION.md](OPTIMIZATION.md) §5).

```sh
scripts/resources.sh &&
cargo fmt --all --check && cargo clippy --workspace --all-targets -- -D warnings && cargo test --workspace
(cd ui && npm run typecheck && npm run lint)
scripts/check-docs.sh   # includes markdownlint, with the same version and rules as CI
```

- Chain them with `&&`: commit only when all pass.
- Commit messages follow Conventional Commits with the requirement ID, for example `feat(stamp): … [FR-004]` ([STYLE_RULE.md §5](STYLE_RULE.md#5-git)). No co-author lines.
- New source files start with `// SPDX-License-Identifier: GPL-3.0-only`.
